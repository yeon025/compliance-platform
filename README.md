## 프로젝트 개요

**문제 정의**

- 컴플라이언스 인증에 필요한 산출물을 Word/Excel 기반으로 분산 관리
- 산출물 갱신 시 어디를 수정해야 하는지 파악이 어려움
- 문서별 버전이 따로 관리되어 이력 관리가 비효율적
- 전체 현황을 한눈에 파악하기 어려움

**해결 방안**

- 분산된 Word/Excel 산출물을 하나의 플랫폼으로 일원화
- 산출물의 갱신 내역과 변경 이력을 체계적으로 추적
- 중앙 통합 관리 체계 구축으로 업무 효율성 향상

## 트러블슈팅

### API마다 로그 형식이 다르거나 누락되어 에러 추적이 어려운 문제

**문제 상황**<br>
API마다 개발을 담당한 개발자가 달라 로그 형식이 제각각이었고, 로그가 아예 남지 않는 API도 있어 에러 발생 시 원인 추적이 어렵다는 요청이 있었습니다.

**최종 선택**<br>
Spring Interceptor를 적용하여 모든 API 호출의 시작과 종료 시점에 로그가 자동으로 남도록 중앙화하고, 비즈니스 로직 코드에서 로그 관련 코드를 분리했습니다.

**결과**<br>
종료 로그가 누락된 구간을 확인하는 것만으로 에러 발생 지점을 빠르게 좁힐 수 있게 되었습니다.

---

### 템플릿 타입 확장 시 테이블 중복 및 코드 수정 문제

**문제 상황**<br>
요구사항에는 ISO 27001, ISMS-P 두 가지 템플릿 타입만 있었지만, 운영 중 추가 템플릿 도입이 예상되는 상황이었습니다. 템플릿마다 계층 구조는 다르지만, 담당자 할당과 응답 처리 로직은 템플릿과 무관하게 동일하게 동작해야 했습니다.

**원인 분석**<br>
템플릿을 하나로 통합해서 관리할 경우, 서로 다른 계층 구조를 하나의 테이블로 표현하기 어려워 확장이 어려웠습니다. 
반대로 템플릿 타입별로 테이블을 나눌 경우, 템플릿과 무관해야 할 담당자 할당 / 응답 처리 로직이 템플릿마다 중복 구현되었습니다.

**최종 선택**<br>
템플릿과 무관한 담당자 할당 / 응답용 중간 테이블로 AssignmentNodeRegistry, ResponseNodeRegistry를 두고, 각 템플릿의 계층별 엔티티와 연결하는 구조를 선택했습니다.

**결과**<br>
신규 템플릿 추가 시 기존 코드 수정 없이 확장이 가능해졌습니다.
